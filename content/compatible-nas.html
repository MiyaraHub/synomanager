Why there is no matrix

Discovery, not a hard-coded list

A per-model support table would be wrong the day Synology released a model, and wrong again the day one of them gained a package.

  • The app queries DSM's API catalogue on connect and keeps the answer. That catalogue is the ground truth for what your NAS can do.
  • Screens appear because your NAS reported the API behind them. Install Surveillance Station and a Cameras view appears. Uninstall it and the view goes.
  • Nothing is assumed from the model name. Two identical models with different packages get different apps, which is correct.
  • A value the NAS did not report is named as unread, never filled in with a plausible default.

The practical version: if DSM's own web interface works from your phone's browser, and your DSM account can see a thing there, Syno Manager can see it too.

Common questions

Compatibility FAQ

Which Synology models does Syno Manager support?
Any Synology NAS running DSM 7.0 or later - DiskStation, RackStation and FlashStation, with or without expansion units. There is no per-model list because the app asks your NAS what it can do when it connects.
Does it work on DSM 6?
No. DSM 7.0 or later is required. DSM 6 uses different API versions and authentication behaviour.
Will it work on a small two-bay NAS?
Yes. It shows fewer screens because it runs fewer services, not because it is unsupported. Everything it does run is shown in full.
Does it support expansion units?
Yes. Drives in an expansion unit appear alongside the internal ones.
What if my NAS runs a beta DSM?
It will generally work, since the app reads the API catalogue rather than assuming a version. A beta that changes an API can produce a value the app reports as unread - which it will say, rather than showing a wrong number.
